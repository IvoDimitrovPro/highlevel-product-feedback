# MR-007 — Unified recording → transcript → AI post-meeting flow

**Product:** Meeting Room
**Type:** Feature
**Status:** Acknowledged
**Date reported:** 2026-09-25
**Source:** [Meeting Room beta response](https://github.com/IvoDimitrovPro/highlevel-product-feedback/blob/main/sources/highlevel-meeting-room-response-2026-09-25.md)
**Impact:** High


## Observed
Recording, transcription and AI processing are still separate steps.

## Why it matters
Recurring client/team meetings should produce usable notes and assets automatically.

## Expected
Per-room/session settings for auto-record, auto-transcribe, AI summary/action items, CRM save and optional replay publishing.

## HighLevel response
HighLevel agrees recording, transcription, AI summaries, and post-meeting processing should work as one configurable flow; feedback noted.

## Live webinar test follow-up — 2026-11-13

**Source:** [Sanitized test notes](https://github.com/IvoDimitrovPro/highlevel-product-feedback/blob/main/sources/meeting-room-webinar-test-2026-11-13.md)

In the 2026-11-13 live webinar test, recording was a manual host action; the user needs optional per-room/session auto-start of recording **and** transcription, with participant notice, so a live presenter cannot forget either. [HighLevel states](https://help.gohighlevel.com/support/solutions/articles/155000009149-meeting-room-in-highlevel-overview) recording does not automatically create a transcript. This is covered by the existing unified recording pipeline request, not a new duplicate.
