Premium Channels, connected to existing products

Two interactive English prototypes of the same private channel in The Club. Compare today’s standalone channel checkout with the proposed product-linked flow. The Community shell stays the same.

Prototype only · sample prices, members and posts · no real payments or external account changes. The Club branding comes from the supplied community. This is a recreated interface, not HighLevel production code.

Explore the proposal

  1. Compare the current behavior. Open Current → Locked guest → Join channel. It sells a standalone channel subscription. Show Channel settings → Pricing: Free, Recurring and One-time.
  2. Configure the proposal. Switch to Proposed → Channel settings → Pricing. Keep Existing Product / Offer, select Club Course and 90 days. Add Club Membership, with access while the subscription is active. Save Changes.
  3. Show the member’s choice. The locked channel now shows both offers with their existing prices and the included access. Open either offer. The checkout/sales-page handoff is simulated.
  4. Buy and return. Simulate a successful order. The same channel opens with a featured post and two feed posts. A failed payment keeps the posts locked.
  5. Recognize an existing buyer. Open Proposed → Existing buyer → Sign in to check access. A verified sample course customer enters without a second order. A member without a qualifying purchase stays locked.
  6. Use one purchase for several channels. Open One purchase · 2 channels. Complete one sample Club Course order, switch between the meeting channel and Course Library, then advance time. The meeting benefit expires; lifetime library access remains.
  7. Set any access period. In Channel settings → Pricing, select Custom number of days and enter a positive whole number, such as 45. Save: the guest offer and checkout show that period.
  8. Unlock with an existing form, quiz or survey. Use Embedded access for a sample form. In Channel settings → Pricing → Custom access, choose an existing asset and inline/popup display. Final completion unlocks automatically; a paid form waits for payment confirmation. No channel-specific workflow or edits to the asset are needed.
  9. Use a simple external funnel link. Open External funnel: only the channel description and a button appear. In Custom access choose Description + button, set the destination and label, and keep native checkout context for automatic return/access. Link-only mode leaves access to your existing automation.
  10. Show safe expiry. Use Bonus expires → Expire course bonus. The membership keeps the channel unlocked. End remaining membership: only then does the channel lock again.
  11. Review the implementation target. Open Order attribution. The existing order identifies the purchased offer and channel origin; other purchase routes retain their original source. Finish on the developer brief linked below.

Use the top buttons to jump between scenarios. Reset restores the original sample settings. Configuration survives reloads in the same browser tab. Current and Proposed keep separate settings.

Boundaries for developers

Payment and order verification belong on the server. The browser cannot grant access. Handle verified orders from every sales route, renewals, refunds, duplicate events, cancellations and expiry against individual grants. Reuse the existing checkout and content tools. The requested native completion/context bridge grants channel access without requiring a workflow per form or channel. A generic external URL cannot prove successful completion by itself; preserve the verified completion/payment boundary.

The prototype demonstrates responsive web behavior. It does not verify the native GoKollab mobile app. Existing-customer recognition, per-channel periods and custom durations are demonstrated. Historical backfill requires explicit review, and broader points/tags/membership conditions remain in the implementation brief.
